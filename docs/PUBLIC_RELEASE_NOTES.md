## 接续开发时优先保留的回归场景

1. 历史消息容器缺失时应拒绝整窗文本兜底，工具栏和其他会话预览不得成为群消息。
2. 同一气泡在时间标签变化、切窗、滚动和重启后应保持稳定归并；真正重复发送的两条相同正文不能被误合并。
3. 会话目录只接受可信节点来源，搜索标签、按钮和聊天正文不得成为联系人或群。
4. 发送全过程应恢复适用的焦点、光标和剪贴板状态，不能只验证局部函数。
5. 转发包标识必须跨重启唯一，旧消息回查不能被新包覆盖。
6. 标题识别须排除视口顶部的长消息；状态缓存不能替代当前窗口证据。

后续 Wave v4/v5/v6 已包含针对性整改和协议扩展，具体代码见当前源码及缺陷台账。公开版验收须独立执行，不能简单照搬首次缺陷或后续历史通过声明。

## 工具链配置

开发脚本不再依赖固定盘符。先运行环境调查，然后使用 PATH 中已确认的 Cargo，或设置以下可选变量：

| 变量 | 用途 |
| :--- | :--- |
| `QQ_UIA_TOOLCHAIN_BIN` | 本机已安装的 Rust toolchain `bin` 目录 |
| `QQ_UIA_CARGO_EXE` | 需要明确指定时的 `cargo.exe` 完整路径 |
| `QQ_UIA_MINGW_BIN` | GNU 工具链需要的 MinGW `bin` 目录 |
| `QQ_UIA_RUSTUP_HOME` | 已确认的 rustup 数据目录 |
| `QQ_UIA_CARGO_HOME` | 可选的项目级依赖缓存目录；拒绝指向用户 `.cargo` |

默认 Cargo/Target/TMP 均位于本项目 `.cache/`。现有用户级 `.rustup` 可以只作为已安装工具链使用，不会因此把 Cargo 缓存写回用户 `.cargo`。实际 QQ 路径与授权目标请写入被忽略的本地配置，再通过 `--config` 传入。
